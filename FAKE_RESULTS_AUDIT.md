# Glossa — аудит `experiments/results/*.json` на предмет симулированных данных

Дата: 2026-07-18. Только инвентаризация фактов — ничего не переписано и не
удалено. Не добавлен в git (как и `AUDIT.md`).

## Метод

Для каждого из 10 файлов `experiments/results/*/results.json`:
1. Найден соответствующий `experiments/*/run.py`.
2. Проверено: есть ли захардкоженный словарь-заглушка (`_SIM*`/`_SIMULATED`)
   и совпадает ли он **побайтово** с числами в `results.json`.
3. Проверена git-история файла (`git log --follow`).
4. Где возможно — сверено с реальными числами, полученными в этой сессии
   (RTMW val_acc, реальный latency из логов api-gateway и т.д.).

## Главный факт, определяющий всё остальное

**Все 10 `results.json` добавлены одним и тем же коммитом
`8e673bb` (2026-06-20, "results: add experiment metrics from
eval_gesture") и ни разу не изменялись после этого** (`git log --follow`
для каждого файла — ровно один коммит). Реальные повторные прогоны
(особенно 09_cross_validation с разными фолдами/сидами) почти всегда дают
хоть немного другие числа при перезаписи — здесь ни один файл не
перезаписывался вообще, что само по себе аргумент в пользу "сгенерировано
разом", а не "измерено и обновлено по мере работы".

README.md сам по себе честен на этот счёт (`README.md:88-89`):
> Числа получены в dry-run режиме на основе архитектурных характеристик
> моделей (раздел 3.3 дипломной работы). Реальные замеры — `make exp-dry`
> или `dvc repro`.

То есть проект **не скрывает**, что это dry-run — вопрос в том, попали ли
эти числа в текст диплома БЕЗ этой оговорки. Файл `diploma_text.txt`
лежит только локально (`.gitignore:1-2`) — прочитать и проверить это я не
могу, см. раздел "Требует ручной проверки" в конце.

1. **Содержимое `diploma_text.txt`** — гитигнорено, локальный файл. Единственный
   способ узнать, какие именно из этих чисел (0.891, WER 11%, E2E P95=977мс
   и т.д.) реально вставлены в текст защиты дословно, без оговорки "dry-run" —
   открыть и грепнуть этот файл самостоятельно по числам из таблицы выше.
2. **`notebooks/colab_glossa_01_train_stgcn_64_200.ipynb`** (без суффикса `a`) —
   более старый ноутбук с собственной ячейкой "ВЫВОДЫ ДЛЯ ДИПЛОМА" — не
   сверял его вывод с `experiments/results/`, может содержать третий,
   независимый набор цифр.
3. **Источник "Sber paper, Table 3"** (эксперимент 07) — существует ли эта
   работа реально и правильно ли процитированы `utmos`/`hvr_win_rate` —
   вне моих возможностей проверить без доступа к самой публикации.
4. **Приоритет перепрогона** — какие из 5 экспериментов, для которых реально
   можно получить настоящие числа (03, 04, 09 — инфраструктура уже есть;
   00/01 — можно взять уже готовые реальные числа из `eval_report.html`
   этой сессии), стоит перепрогнать до защиты, а какие честно пометить как
   "оценка, не измерение" — решение по приоритетам и оставшемуся времени,
   не техническое.
