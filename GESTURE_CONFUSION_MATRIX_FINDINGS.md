# Реальная confusion matrix — находки

Дата: 2026-07-19. Не добавлен в git. n=1000, 200 классов,
`data/gestures/processed_64_200/val`, `models/gesture_classifier.onnx`.

## Как получено

`mlops/pipelines/eval_gesture.py` был сломан в трёх местах (нашёл, пытаясь
его реально запустить, не по коду):
1. `test_dir` указывал на `processed/test` — устаревший T=32/1000-класс
   датасет, несовместимый с текущей моделью, и без сплита `test` вообще
   (только `train`/`val`). Поправлено на `processed_64_200/val`.
2. `class_names_path.read_text()` без `encoding="utf-8"` — падает на
   Windows (cp1252 не может декодировать кириллицу). Поправлено.
3. `_write_confusion_csv`'s `out_path.open("w", newline="")` — та же
   проблема при записи. Поправлено.

Сам полный пайплайн (`python -m mlops.pipelines.eval_gesture`) всё равно
не запустить в этой песочнице — `tracker.start_run()` виснет, пытаясь
достучаться до MLflow на DagsHub (сети нет вообще, подтверждено раньше в
сессии). Прогнал те же inference + метрики в обход `ExperimentTracker`
(тот же код: `_load_onnx_session`/`_run_inference`/`compute_gesture_metrics`
из самого модуля, просто без сетевого трекинга).

**Первая попытка дала accuracy=0.26 — это была ошибка в МОЁМ скрипте**
(забыл применить z-score нормализацию поверх `features.npy`, которая
хранит только hip-center/shoulder-scale нормализованные, но не
z-scored признаки — тот же шаг, что `normalizer.py` и более ранний
`tta_ab_test.py` в этой сессии применяют явно). После фикса —
**accuracy=0.6040**, совпадает по порядку величины с TTA-тестом (0.6280)
на том же val-сете. Не публикую здесь первую (неверную) цифру как
находку — только проверенную.

## Находки

**1. Подтверждён дубликат словаря эмпирически**, не только по
совпадению строк: `'весёлый'` и `'веселый'` — оба с `f1=0.000`, входят в
топ confused pairs (2 переклада друг в друга). Ранее это было гипотезой
по написанию (ё/е); теперь — измеренный факт по confusion matrix.

**2. Новый паттерн — грамматические формы одного слова путаются
систематически**, не по написанию (edit-distance их бы не поймал):
- `бояться` ↔ `боюсь` (инфинитив/1-е лицо) — 5 путаниц, обе с низким F1.
- `вы` / `вас` / `ваш` — кластер из трёх местоименных форм, путаются
  друг с другом попарно.
- `вечность` / `вечный` (существительное/прилагательное).
- `быстро`/`быстрый` — реально путаются, как и предполагалось.
- `возможно`/`возможный` — из аудита словаря, тоже стоит проверить.

Для каждой пары нужен ответ носителя РЖЯ (или документации по языку):
это **один и тот же жест** для разных грамматических форм слова (тогда
это снова проблема словаря — сливать классы, как `весёлый`/`веселый`),
или **разные, но визуально похожие** жесты (тогда это про модель, не
про данные).

**3. Отдельно — кластер тематически близких эмоций, похоже на реальную
визуальную путаницу модели**, не словарную проблему: `возбуждение` ↔
`вдохновлять`, `возбуждать` ↔ `беспокойный`, `возбужденный` ↔
`вдохновлять`. Разные слова, не связаны грамматически — вероятно,
жесты для эмоциональных состояний в этой части словаря визуально близки,
и это именно то, что должен решать шаг с исправлением графа/нормализации
(`docs/KNOWN_LIMITATIONS.md`), а не чистка словаря.

## Что дальше

`eval_gesture.py` теперь рабочий (3 бага исправлены) — на VM с реальным
доступом к MLflow можно прогнать полный пайплайн с трекингом:
```bash
python -m mlops.pipelines.eval_gesture --model-path models/gesture_classifier.onnx
```
даст те же метрики, но с полным MLflow-трекингом и сохранением в
DVC-отслеживаемые `mlops/reports/`.
